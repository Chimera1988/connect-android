## Реализация

Одна WebView отображает встроенные React-компоненты, CSS, сцены, SVG и графику текущей PWA. Отдельных WebView для сообщений, нативных дублирующих панелей и второго движка звонков нет. PWA WebRTC-контроллер не монтируется; нативный WebRTC/Telecom управляется PWA-экраном через проверяемый мост. Все API, аккаунты и файлы остаются в действующем Connect/Supabase. Сервер, схема, RLS, базы и эталонный репозиторий не менялись. Secret/service-role ключей в клиенте нет.

JavaScript-мост проверяет HTTPS origin, nonce, версии/размеры/форму команд, UUID и идентификаторы текущего вызова. Навигация к новым документам запрещена. Записи передаются блоками с подтверждением получения, лимитами, отменой и очисткой. Графика читается из APK через ограниченный appassets interceptor без file:// universal access. Системный выбор файлов использует SAF; экспорт и blob-download передаются потоком в выбранный пользователем документ. Сессии синхронизируются в обе стороны; прежние настройки, скрытие сообщений, избранное и личный фон импортируются без удаления SecureStore.

Перенесён актуальный PWA UI: Liquid Glass, точная трубка, сообщения/ответы/поиск/пересылка, альбомы/медиа/GIF, стикеры, профиль/музыка, темы, приглашения и скрытые участники. Это перенос рабочего исходного кода, а не доказательство исполнения каждого сценария на телефоне. Старые 199 текстовых признаков не используются как процент готовности; их требование «без WebView» заменено новым ТЗ.

Скролл сохраняет якорь, открывает первое непрочитанное, удерживает положение при изменении размеров и входящем сообщении во время чтения. Удаление последнего сообщения различается с добавлением нового. Обработка видимых сообщений ограничена видимым диапазоном; убраны постоянные compositor transform со всех пузырей. Поддерживающий WebView может пропускать отрисовку невидимых сообщений только после измерения их настоящей высоты. Голосовые мемоизированы, волны декодируются лениво и кешируются. Постоянного scrollToEnd нет.

Голос записывается нативно в финализированный AAC/M4A, видеокружки — встроенной CameraView в MP4 с круглым preview/отменой/отправкой. В плеере голоса время и статусы находятся внутри; лишняя кнопка сохранения убрана. Видеокружки используют правила видимости PWA. Системные звонки исключительно аудио, камера используется для вложений/видеокружков.

## Выполненные проверки

- `npm run build:web`, `npm run typecheck:web`, `npm run typecheck`.
- `npm test`: 14 файлов тестов; сценарии чтения/доставки/ICE/аудиозвонков/волн, настройки/экспорт, безопасность протокола, миграция и appassets.
- Expo Android prebuild, синтаксис плагинов и `git diff --check`.
- `verification/browser-parity.cjs`: исходная PWA и гибрид при одинаковых 390×844, синтетические аккаунты/REST. Вход, отсутствие удалённых сообщений, возврат в чат и входящее сообщение сохраняют якорь в пределах 2px, профиль, семь тем, Android Back. Скриншоты в `verification/`.
- `verification/bridge-runtime.cjs`: именно финальный inline HTML запускается в Chromium с подменой native transport; handshake, побайтовая передача записи с ACK, экспорт, флаг разрешения fullscreen. Это не Android WebView.
- CSS fixtures для стикеров/профиля/тем и метаданных голоса.
- Действующий HTTPS proxy отвечает; `/api/calls/ice` без токена возвращает 401. Это проверка доступности и защиты, а не успешного звонка или RLS скрытого пользователя.

Измерения: `verification/browser-parity.json`. Последний desktop software-rendering прогон 500 текстовых сообщений: открытие 475ms, медиана rAF 100ms, p95 183.3ms, JS heap около 13.3MiB. Это НЕ 60 FPS и не доказательство производительности Android. При параллельной компиляции результаты были ещё хуже. Цель 60 FPS на телефонах остаётся неподтверждённой; аппаратного профиля RAM/GPU/пропущенных кадров нет.

Полная Kotlin/Java-компиляция завершилась успешно. C++ appmodules и Expo для обеих ABI собраны в предшествующих шагах; итоговая упаковка повторно использовала эти неизменённые библиотеки с исключением четырёх повторных CMake build-задач. ELF/ABI/JNI_OnLoad и SHA-256 сохранены в `verification/native-library-build.json`; новых C++ исходников после компиляции не было. Java/Kotlin, lint и проверка APK не отключались. Финальный `assembleRelease` успешен: 597 задач, 167 выполнены, 430 актуальны. Это инкрементальная локальная сборка, а не утверждение о завершённом чистом CI-прогоне.

В одноразовом окружении 7.9GiB не помещались одновременно полный NDK, все кеши и APK. Использованы дедупликация одинаковых результатов, очистка временных кешей и сокращение вспомогательного NDK; после завершения C++ удалены временные копии compiler/linker. Широкое дальнейшее удаление SDK было отклонено автоматической проверкой и не выполнялось. Для чистой пересборки необходим полный NDK 27.1.12297006 и достаточный диск; подготовленный GitHub workflow предусматривает обычную сборку с полным SDK. Скрипты не требуют применения отдельных YAML-патчей.

Нативных JUnit-тестов в проекте нет; release unit-test variant отсутствует в Expo-шаблоне. Локальный `testDebugUnitTest` не запускался. Доступная задача указана в будущем CI workflow; успешные JS-тесты и компиляция не выдаются за нативные JUnit или испытания на телефоне.

## Неподтверждённая приёмка

Устройств adb и эмуляторов нет, `/dev/kvm` отсутствует. Установка/запуск APK на Android10–15+, лаунчер, системная клавиатура/IME-стикеры, вырезы, реальные разрешения/кодеки, длительность и звук записей на двух устройствах, видеокружки, FCM в фоне/после закрытия/lockscreen, очистка шторки между устройствами, полные звонки/потеря сети/Bluetooth/аудиофокус/системная громкость/DND/вибрация, native incoming без splash, музыка в фоне и реальные кастомные мелодии не проверены.

Сравнения Android screenshots с PWA нет; выполнено только сравнение desktop Chromium. Доказательств закрытия всех 199 сценариев и всех аппаратных требований нет.
