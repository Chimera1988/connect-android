# Connect 2.2.2 (12): звонки, клавиатура, иконка

Android-база: 19547b77e229ca0c50cd21f4c0c51f03229b3acd, исходники поставленного APK 2.2.1 (11). Android origin/main 1982fa8 старее этой сборки и не использован для отката. PWA проверена по main 65b713b; более новые визуальные изменения сохраняются. Один основной агент, без промежуточных пользовательских APK. В GitHub изменения не опубликованы: право записи ранее возвращало 403.

## Что изменено

Звонком владеет нативный ConnectCallService: org.webrtc PeerConnection/аудиоустройство, существующие Supabase RPC/ICE, один self-managed Telecom ConnectionService и существующая ConnectIncomingCallActivity. React Native теперь вызывает тонкий интерфейс координатора. WebView/React не управляют фоновым жизненным циклом. Удаление из недавних задач само по себе не завершает разговор; принудительную остановку через настройки Android приложение не обходит.

Один callId управляет состоянием, сигналами, экраном и уведомлением. Реализованы IDLE, PREPARING, REMOTE_RINGING, INCOMING, CONNECTING, ACTIVE, RECONNECTING, ENDED, DECLINED, MISSED, BUSY, FAILED. Серверный active означает принятие; локальный ACTIVE требует соединения WebRTC, удалённой аудиодорожки и запуска записи/воспроизведения аудиомодуля. Генерации, проверка владельца/аккаунта/срока, терминальные метки и последовательности состояния защищают от повторных и устаревших событий. Завершение идемпотентно освобождает сигналы, микрофон/PeerConnection, фокус, WakeLock, Telecom, уведомление и таймеры. Неотправленные завершения сохраняются для повторной отправки; восстановление сети ограничено тайм-аутом.

Входящий обрабатывается нативным FCM receiver. На первом обновлении ещё не перенесённая сессия может пройти прежний Headless bootstrap; затем работает тот же нативный координатор. Сессия переносится из Expo SecureStore в AES-GCM/Android Keystore без сброса авторизации. Обновление/регистрация FCM-токена имеют нативный JobScheduler-путь. Секреты не передаются через Intent/логи. Сообщения сохраняют независимый прежний путь обработки уведомлений.

Единственный владелец звуков — ConnectCallAudio; канал звонков без звука. Приоритет рингтона: выбранный файл Connect, затем актуальный Android TYPE_RINGTONE. Звук сообщения не используется как рингтон. Вибрация 450 мс / пауза 850 мс повторяется до остановки с учётом системного режима, громкости, DND и настроек. Недоступный URI даёт диагностический код без секретов. Гудки Connect: 440+480 Гц, два импульса по 450 мс с началами 0/640 мс, цикл 3,6 с. После фактической готовности аудио один раз звучит 740 Гц/120 мс + 988 Гц/190 мс. Старый startRingback('_DEFAULT_') и конкурирующий CallKeep вызовов не используются.

Входящий экран не запускает MainActivity/splash; принятие/отклонение/управление разговором выполняются нативно. Foreground service начинает входящий с типом phoneCall, microphone добавляется при видимом действии пользователя и разрешении. Android 14+ использует разрешённый full-screen intent либо системное CallStyle-уведомление. Видеозвонки не добавлены; камера по-прежнему нужна видеокружкам.

Клавиатура: adjustResize, расчёт реально доступной WebView-высоты, API 29 fallback и API 30+ IME insets. Уже выполненное Android уменьшение не вычитается повторно. Обработчик удаляется при уничтожении WebView.

Иконки взяты из предоставленного ZIP без перерисовки: adaptive background/foreground/monochrome и legacy/round для пяти плотностей. В финальном APK проверены 13 PNG: альфа и видимые RGB-пиксели совпадают. AAPT нормализует только невидимые RGB полностью прозрачных пикселей. Сохранены com.connect.messenger, название Connect, Android 10/API 29 минимум.

## PWA и сервер

PWA прекращает локальное ожидание при ответе другого устройства, проверяя принятый SDP. Запоздавшие microphone/TURN/SDP/RPC-ответы прежнего вызова не закрывают следующий. Двойное принятие блокируется. Ошибка проигравшего устройства не отправляет failed/hangup уже принятому разговору. ACTIVE не устанавливается по нажатию «Ответить».

На рабочем Supabase применена узкая миграция connect_call_response_owner_v1: decline/busy после перехода в active игнорируются. Повторная проверка подтвердила защиту и прежние SECURITY DEFINER, ACL, аргументы RPC. Пользовательские строки, история, Storage, таблицы и RLS не менялись. SQL и guarded rollback включены в ZIP/YAML. Рабочие пользовательские звонки для тестов не создавались.

connect-final-unified-update.yml содержит только PWA-фикс звонков, новые тесты и этот SQL. Проверяет preimage и зависимости, повторный запуск, сохраняет несвязанные новые CSS/видео-изменения. Выполняет npm ci, typecheck, прежние/новые тесты и Next production build перед коммитом. При отказе GitHub push честно сохраняет результат в Actions artifact. Сервер workflow автоматически не меняет: узкая защита уже применена отдельно. Публичная PWA ещё не обновлена: YAML нужно загрузить в .github/workflows и запустить workflow_dispatch.

Общий исправленный компонент сохранён и в Android. Его браузерный контроллер там не монтируется и удаляется Vite. Встроенный HTML до/после совместимого PWA-изменения побайтно одинаков, поэтому дополнительная APK-сборка не требовалась. Сохранены прежние исправления медиа/стикеров 2.2.1 и утверждённый дизайн.

## Проверки

- Native TypeScript, shared web TypeScript, Vite production bundle 856820 байт — успешно.
- Все 17 native Node test-файлов — успешно, включая bridge/cancel/double-tap/generation, keyboard/icons.
- 12 настоящих Kotlin/JVM JUnit-тестов — успешно: состояния, частоты/интервалы PCM, 5000 повторных вызовов, TTL/владелец/смена аккаунта, устаревшие события.
- Обычная полная Gradle assembleRelease + lintVitalRelease + testReleaseUnitTest — BUILD SUCCESSFUL: 610 задач, 29 выполнены, 581 актуальны. Без пропуска компиляции/lint.
- Chromium, реальный гибридный React/CSS: 4 сценария клавиатуры overlay/resize на ширинах 320/390; поле ввода видно, нет двойного уменьшения, якорь стабилен, закрытие восстанавливает высоту. Это синтетический IME.
- 11 новых тестов гонок PWA + PostgreSQL-тест защиты — успешно. Прежние 4 crypto primitive, SQL migration, persistent-cache, media и service-worker проверки — успешно. Crypto primitive не означает включённое E2EE.
- YAML actionlint, первое применение к проверенному main, повтор, отказ при изменении звонков/зависимостей, сохранение постороннего CSS — успешно.
- APK: CRC/подпись, версия 2.2.2 (12), API 29, не debuggable, ARM32/64, встроенный Hermes JS, ресурсы/DEX, единственный Telecom owner, точные видимые пиксели иконок, отсутствие закрытых ключей/keystore — успешно. Metro/Expo Go не нужны.

Новый PWA Next production build локально не выполнялся: полный Next dependency tree в сохранённом окружении отсутствует; проверка обязательна в доставленном workflow. Изменённый общий TSX проверен Android web TypeScript. Это ограничение не заменяется успешной Android-сборкой.

## Что остаётся неподтверждённым

ADB не обнаружил устройств; эмулятор/KVM отсутствуют. Не проверены установка/запуск на телефоне, реальные Android↔Android/PWA звонки и TURN, FCM в фоне/холодном процессе, звонок после непрочитанного сообщения, блокировка/FSI Android 10 и 14+, фактические рингтоны/свои файлы/вибрация/DND, Bluetooth/аудиофокус/громкость/переподключение, настоящие клавиатуры и launcher masks. iPhone PWA с микрофоном, ответ двух устройств и длительная работа тоже требуют устройств. Модельные тесты не заменяют аппаратные. Гарантия 60 FPS не установлена.

Оригинальный release-ключ недоступен. Использован прежний резервный Android Debug сертификат SHA-256 fac61745dc0903786fb9ede62a962b399f7348f0bb6f899b8332667591033b9c. Он точно совпал с исходным APK 2.2.1 (11); для этого APK подпись совместима, versionCode увеличен. Сертификат иной установленной версии неизвестен; установка поверх неё не гарантируется. Удалять приложение ради проверки не требуется. Это release build с резервной подписью, а не подпись оригинальным release-ключом.

Большое предыдущее ТЗ не объявляется полностью завершённым: E2EE по умолчанию, доверенные устройства/перенос истории, E2EE-сигнализация, физический сборщик Storage, общая статистика кеша и аппаратная приёмка остаются незавершёнными/неподтверждёнными. E2EE в 2.2.2 НЕ включено. Само его отсутствие не объясняет прежние ошибки аватаров/стикеров.

Telegram Calls/VoIPService/TelegramConnectionService изучены как архитектурный образец; код, UI и звуки Telegram не копировались. Использована существующая инфраструктура Connect/Supabase/FCM/WebRTC/Telecom.
